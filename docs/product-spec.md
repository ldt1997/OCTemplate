# 产品规格

## 项目背景

OCTemplate 提供多种可参数化配置的图片模板。用户通过模板、图片和表单参数生成视觉风格统一的图片，并可在浏览器端和移动端完成预览与导出。

项目当前已具备：

- 首页模板列表
- 模板页面路由
- 参数工具栏
- 固定尺寸或基于上传图片尺寸的预览画布
- 图片上传、缩放和位移
- 本地图片和字体资源
- Canvas 导出 PNG
- 浏览器端和移动端自适应布局

## 目标用户

- 想快速生成统一视觉图片的个人创作者。
- 想复用某类视觉模板并替换角色图、文字、颜色等参数的内容制作者。
- 后续维护和新增模板的开发者或 AI 编程助手。

## 核心使用场景

典型流程：

1. 用户进入首页。
2. 用户选择一个模板。
3. 用户上传人物、角色或背景图片。
4. 用户在工具栏中调整文本、颜色、图片位置、缩放等参数。
5. 用户在画布中实时预览效果。
6. 用户点击导出，下载固定规格的图片。

## 产品原则

- 模板优先：页面核心是生成图片，不做营销型落地页。
- 参数清晰：每个表单项都应对应明确的视觉结果。
- 预览可信：用户看到的预览应尽量接近最终导出。
- 移动可用：移动端不要求完整桌面效率，但必须完成核心流程。
- 轻量迭代：新增模板时先实现核心能力，再补充复杂交互。

## 页面架构

### 首页

首页展示模板列表。每个模板卡片应包含：

- 模板名称
- 模板分类或标签
- 简短描述
- 预览图
- 跳转路径

首页不承载模板编辑逻辑。

### 模板页

模板页由以下区域组成：

- Header：展示站点导航和导出按钮。
- Toolbar：承载模板参数配置。
- Viewport：承载画布显示区域，处理可用空间测量和展示尺寸。
- Canvas：显示模板预览。

桌面端推荐布局：

- Toolbar 固定在左侧。
- Canvas 占据剩余区域。
- Header 中放置导出按钮。

移动端推荐布局：

- Canvas 优先占据主视图。
- Toolbar 通过底部抽屉、底部面板或 Tab 呈现。
- 导出按钮保留在 Header 或明显的操作区域。

## UI 风格

项目整体倾向轻量、清晰、工具化。

默认风格：

- 使用 shadcn/ui 基础组件。
- 使用 Tailwind CSS 组织局部样式。
- 使用 lucide-react 图标。
- 控件外观保持克制，不做过度装饰。
- 扁平简洁，不使用无必要的渐变，圆角，边框和阴影。
- 模板最终画面可以有强风格，但编辑器 UI 应保持稳定和易用。

## 模板体验要求

模板页面应做到：

- 表单修改实时影响预览。
- 导出尺寸不受屏幕尺寸、预览缩放和设备像素比影响。
- 上传图片后可以清晰反馈错误，如文件类型或大小不符合要求。
- 图片资源和字体资源未准备好时，不应给出错误的导出结果。
- 移动端至少支持上传、修改参数、预览和导出。

## 暂不优先的方向

以下能力不作为新模板默认要求：

- 多图层自由编辑器。
- 通用场景引擎。
- 模板市场或账户系统。
- 云端存储。
- 多人协作。
- 复杂历史记录和撤销重做。

这些能力只有在多个模板反复需要时，再考虑抽象或产品化。
